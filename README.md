# GoGoGo

Android 横屏优先的高位斜俯视第三人称 PvE 射击游戏，使用 Godot 4 开发。

完整冻结设计见 [`docs/design/GDD-MVP-v0.1.md`](docs/design/GDD-MVP-v0.1.md)。

## 当前实现

第一条核心垂直切片已经包含：

- Godot 4 Mobile 工程与 1280×720 横屏基准。
- 固定方位高位斜俯视镜头。
- 4.5 m/s 玩家平面移动与独立朝向。
- Android 左移动摇杆、右瞄准摇杆和可拖动调向的独立射击键。
- 键鼠调试输入：WASD、鼠标瞄准、左键射击。
- 永久标准手枪加一个特殊武器槽；右上角按钮或键盘 `1/2` 可随时切换。
- 标准手枪、重型手枪、机枪和火箭枪全部由 WeaponDefinition 驱动射速、弹匣、备用弹药与换弹。
- 半自动武器按次射击，机枪按住连续射击并具有确定性散布增长与恢复。
- 特殊武器使用有限备用弹药，弹匣打空自动换弹，全部弹药耗尽后自动切回标准手枪。
- 10 米 CQB 即时射线、真实碰撞截断与常驻分段瞄准线；射程比 12 米视野短 2 米。
- Android 轻度瞄准吸附：只修正有效视野内靠近瞄准线的警卫，不穿墙、不超距、不自动开火。
- 火箭以 10 m/s 飞行，最远 10 米，碰撞或到达射程后产生半径 4 米、中心 5/边缘 1 点的无阵营爆炸。
- 地图放置四件特殊武器：空槽自动拾取、同类自动补弹、异类显示确认按钮；换下的武器保留当前弹匣和备用弹药掉落原地。
- 玩家从出生点前往至少 18 个模块外的任务点，在范围内停留 3 秒自动激活；离开清零，受伤不中断。
- 任务激活后所有存活警卫只获知任务点位置并前往调查，HUD 目标箭头切换回出生撤离点。
- 撤离点激活前不可完成关卡，任务完成后进入出生点范围立即获胜，不要求消灭最后一名警卫。
- HUD 持续显示目标方向、近/中/远距离、剩余警卫和激活进度；胜负结算显示用时、击杀、剩余生命与撤离结果。
- 新游戏生成本局随机种子，并从手工验证候选点一次性布置 8–12 名警卫、远端任务点、4 件特殊武器和 2 个急救包。
- 特殊武器预算保证重型手枪、机枪、火箭枪各一件，第四件从三类中随机重复。
- 急救包在受伤时自动恢复 2 格，满血不会消耗；急救包和武器拾取物在玩家盲区中隐藏。
- 失败结算可重试同一种子并恢复完整开局布局、生命和物资；“新游戏”会生成新种子与新布局。
- 5 点耐久的独立木墙模块，命中 5 次后移除。
- 玩家生命和基础 HUD。
- 共享的 120°、12 米 VisionSensor3D，玩家与警卫使用同一角度、距离和墙体遮挡算法。
- 会被砖墙和木墙实时裁切的地面视野扇形；headless 测试时自动跳过纯视觉网格。
- 3 点生命手枪警卫：巡逻扫描、0.6 秒首次预警、0.2 秒射击锁向、最后位置搜索。
- 玩家盲区中的警卫默认隐藏；开火后显形 2 秒，进入墙后只留下静止位置标记。
- 盲区静态地形和墙体保留轮廓但暗化、降饱和；警卫、武器和急救包继续隐藏。
- 盲区火焰不显示精确火区，火焰与爆炸只在 HUD 显示 1 秒的大致方向提示，不会照亮附近动态单位。
- 集中式声音事件：标准手枪声传播 24 米、玩家脚步传播 4 米、木墙摧毁声传播 20 米。
- 警卫会按声音半径和优先级前往声源调查；目视预警与战斗会覆盖普通声音刺激。
- 与 2×2 米地图模块对齐的二维格子导航，3D 警卫在调查和搜索时沿正交路径平滑移动。
- 砖墙与木墙自动生成阻塞格；木墙摧毁时立即开放格子，警卫在下一物理帧按导航版本重算路线。
- 警卫会在 6 米内选择最近、可达且能遮挡玩家射线的安全掩体，并沿格子路径进入掩护。
- 到达掩体后周期性移动到清晰探身点，执行 0.2 秒锁向单发，再返回隐藏位置。
- 掩体摧毁后同逻辑帧失效并重选；无掩体时按 6–9 米 CQB 距离带后退、接近或横向移动。
- 主要通路加入成对短墙、入口隔断和左右 L 形房间，并使用更近的固定俯视镜头压缩交火空间。
- 石油滚筒墙拥有 4 点耐久，归零后燃烧 4 秒；木墙被火点燃后燃烧 3 秒，两者燃尽后打开缺口。
- 火焰每秒造成 1 点无阵营伤害，并只向中心距 2 米的正交相邻可燃模块传播。
- 汽油滚筒墙拥有 3 点耐久，归零或接触火焰后立即产生 3 米爆炸并消失。
- 汽油爆炸从中心 3 点线性衰减到边缘 1 点，无阵营、无击退，完整墙体会阻挡本次爆炸。
- 燃烧与爆炸通过确定性队列连锁；模块失效时视觉、碰撞和导航同步开放。
- 无第三方框架的 headless 自动测试。

## 运行

使用 Godot 4.7 或兼容 Godot 4 版本打开项目，然后运行主场景：

```sh
godot --path . --editor
```

桌面调试操作：

- `WASD`：移动
- 鼠标：瞄准
- 鼠标左键：射击；机枪可按住连射
- `1` / `2`：切换标准手枪 / 特殊武器

触控控件在主场景中常驻显示；移动端会自动禁用键鼠调试输入。左摇杆负责移动，右摇杆用射线选择敌人：靠近有效目标后自动吸附并锁定，松手后角色、视野与瞄准线继续跟随目标；射击键只负责单击射击或按住机枪连射，不再通过拖动改变方向。锁定不会穿墙、发现盲区目标或让火箭转向追踪。

玩家移动速度为 6 m/s。左摇杆采用 58 px 有效半径、12% 防漂移死区和增强中段响应曲线，半程拖动即可获得约 66% 的移动输出，松手后即时停步。

成功开火会立即触发枪口火光、短暂弹道曳光、枪身后坐和程序化枪声；命中时额外显示撞击闪光，Android 设备提供轻震动。普通弹着点会从碰撞面向射手侧略微偏移，因此砖墙等实体表面不会把标记遮住。反馈监听真实武器 `fired` 信号，冷却或换弹期间的无效输入不会播放假反馈。

实际对敌人造成伤害时会显示更大、更亮的命中确认，并让敌人模型短暂闪红；普通墙面碰撞不会显示伤害确认。玩家受伤时模型闪红、屏幕覆盖短暂红色闪层并播放受击音，Android 设备提供更强的受击震动。

玩家与警卫共用 `assets/models/prototypes/player.glb` 兵人模型，并分别通过玩家青绿色、敌人红色的运行时材质区分阵营。双方场景继续使用各自原有的碰撞体与逻辑枪口，因此模型替换不会改变移动、命中或射击规则。当前原型的角色和手枪是单一网格，切换特殊武器时手持武器外观暂不会改变；后续需将身体与武器拆分为独立网格后再接入三种武器外观。

地图环境已接入 BrickWall、WoodenWall、WoodenCrate、Sandbag、OilDrum、FuelCan、Medkit、MissionTerminal 和 ExtractionBeacon 原型模型。长砖墙由 2 米标准模型重复拼接，木箱与沙袋作为新的静态掩体加入地图；碰撞、导航、耐久、燃烧、爆炸、拾取、任务和撤离逻辑继续由原玩法场景负责。

木墙、石油桶和汽油桶首次受伤后会在模型上方显示 1.8 秒世界空间生命条，并按剩余耐久切换绿、黄、红三档颜色；未受伤或超时后自动隐藏。

后续概念图必须复用 `docs/concepts/GENERATION_PROMPTS.md` 中的固定风格块、阵营色和负面约束，并附带现有标准图作为视觉参考，以保持兵人造型一致。

## 验证

```sh
godot --headless --xr-mode off --path . --check-only --quit
godot --headless --xr-mode off --path . --script res://tests/test_runner.gd
```

当前自动测试验证同种子布局完全一致、不同种子布局变化、8–12 名警卫、远端任务候选、四件特殊武器预算、两个急救包、满血不消耗、受伤恢复和重试状态复原；同时覆盖任务撤离、四类武器、Android 触控、瞄准吸附、盲区静态/动态边界、环境间接反馈、警卫感知与掩体、声音、动态导航、燃烧、爆炸遮挡及环境连锁。

地图使用三面不可破坏模块砖墙构成出生安全庭院，并以 23 段可破坏木墙切分左右侧翼与中北部交战区；木箱和沙袋补充侧翼静态掩体。自动测试保证所有警卫候选均无法在出生点直接看见玩家，离开出生区的首段路线同时最多暴露给两名警卫。

## GitHub Actions Android 构建

`.github/workflows/android-build.yml` 只在手动触发时运行：

1. 在 **Actions → Android Build → Run workflow** 输入 Release 标签（例如 `v0.1.0`），并选择是否标记为预发布版。
2. 使用 Godot CI 4.7 容器导入项目、运行语法检查和完整核心回归测试。
3. 使用标签同步 APK 版本名，并通过 `export_presets.cfg` 导出 Android arm64 调试 APK。
4. 创建对应标签的 GitHub Release、自动生成发行说明，并附加 `gogogo-android-arm64-debug.apk`。

构建成功后可在仓库 **Releases** 页面下载 APK；流水线不再保留重复的临时 workflow artifact。同一标签重新运行会更新对应 Release。调试 APK 用于真机安装与测试，不包含正式上架签名。

流水线会将 Godot CI 镜像中与 4.7 匹配的 EditorSettings 复制到 Actions `HOME`，显式验证 Java 17、Android SDK 33、Build Tools 33.0.2、导出模板和 fontconfig，任一依赖缺失都会在导出前给出清晰失败。
